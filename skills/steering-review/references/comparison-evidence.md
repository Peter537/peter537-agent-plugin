# Comparison evidence and counterexamples

## Match the evidence to the claim

A source inspection can establish contradictory conditions, a missing command target, or an unconditional reference-loading rule. It cannot establish what an agent actually did, how much context it loaded, or whether a rewrite improves results.

For an authorized behavioral comparison, freeze the task, packages, relevant repository and Git state, tool capabilities, model/settings, permissions, and expectations. Vary the proposed guidance alone. Keep grading metadata outside the evaluated context. Inspect actual outputs and state; distinguish action records from response summaries. Declare finite execution limits and do not start model trials without their own authorization.

Require a reproduced failure before claiming a behavioral correction. A simplification needs comparable acceptable outcomes and demonstrated clarity, loading, or execution benefit. Source length can be recorded separately, but is not evidence of token, latency, or monetary savings. Existing unrelated failures remain visible; they do not justify lowering expectations.

## Choose a counterexample that matters

| Proposed change | Necessary preservation check |
| --- | --- |
| Narrow a discovery description | Keep intended explicit/natural requests and neighboring ownership; preserve explicit-only policies. |
| Load a reference conditionally | Retain it for tasks that need its safety, privacy, cleanup, or evidence rules. |
| Remove a repeated approval | Continue already-authorized work, but respect diagnosis-only requests, revocation, and newly expanded scope. |
| Consolidate duplicate instructions | Preserve each applicable audience, scope, rationale, exception, and authoritative location. |
| Replace a stale command | Retain required flags and execution context; verify the replacement's actual bounded behavior. |
| Reduce checks for a narrow task | Keep broader checks when an affected contract or authoritative project rule requires them. |

A failed comparison supports rejecting or narrowing a proposal, not another unbounded correction campaign. An already adequate instruction set needs no modification.

## Preserve the distinction between recommendation and adoption

State whether a proposed effect is observed, inferred, or unresolved. When execution is unavailable, describe the smallest useful comparison and its counterexample; do not label the predicted result as demonstrated. Preserve a rule whose necessity remains unresolved until relevant authority or evidence resolves it.

Use supplied historical results only within their recorded revision, task, tools, and permission scope. Repeated accounts of one event are not independent recurrence. A pattern warranting broader learning or a deterministic control belongs to the appropriate separately authorized retrospective/policy workflow; this review does not create persistent memory or promote a new universal rule.
